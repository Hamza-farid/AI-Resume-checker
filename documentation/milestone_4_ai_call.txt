 0️⃣  ⚠️ API KEY vs CLAUDE CODE TOKEN  (our first blocker)
══════════════════════════════════════════════════════════

   ┌────────────────┬──────────────────────┬─────────────────────┐
   │                │ ✅ API key            │ ❌ OAuth token       │
   ├────────────────┼──────────────────────┼─────────────────────┤
   │ Starts with    │ sk-ant-api...        │ sk-ant-oat...       │
   │ Made by        │ console.anthropic.com│ `claude setup-token`│
   │                │ → API Keys           │                     │
   │ Meant for      │ YOUR apps (this one) │ Claude Code only    │
   │ Billing        │ pay per token        │ your subscription   │
   │ Works here?    │ ✅ Yes                │ ❌ No (401 error)    │
   └────────────────┴──────────────────────┴─────────────────────┘

   What happened: .env had an sk-ant-oat token
                  → Claude API said 401 "API key is invalid"

   Fix: 1. console.anthropic.com → API Keys → Create Key
        2. .env →  claude=sk-ant-api...
        3. python tests/test_api_connection.py → should say ✅

   🛡️ The app now detects an sk-ant-oat token and shows a clear
      message instead of a confusing 401.

   🔌 tests/test_api_connection.py
      Step 1: checks key TYPE (never prints the key)
      Step 2: sends "Hi" → prints Claude's reply (almost free)

══════════════════════════════════════════════════════════
 4️⃣  ALL SETTINGS  (config.py, can be changed from .env)
══════════════════════════════════════════════════════════

   ┌────────────────────┬───────────────────┬──────────────────────────┐
   │ Setting            │ Value             │ Why                      │
   ├────────────────────┼───────────────────┼──────────────────────────┤
   │ LLM_PROVIDER       │ claude            │ which AI                 │
   │ CLAUDE_MODEL       │ claude-sonnet-5   │ your choice              │
   │ CLAUDE_EFFORT      │ medium            │ how deeply it thinks     │
   │                    │                   │ (low/medium/high)        │
   │ CLAUDE_MAX_TOKENS  │ 32000             │ upper limit; bill only   │
   │                    │                   │ for real tokens          │
   │ CLAUDE_TIMEOUT_SEC │ 180               │ 3 min per try            │
   │ CLAUDE_MAX_RETRIES │ 1                 │ retry busy/server/net    │
   │                    │                   │ errors once              │
   │ PRICE_INPUT_PER_M  │ 2.0               │ $ per 1M input tokens    │
   │ PRICE_OUTPUT_PER_M │ 10.0              │ $ per 1M output tokens   │
   └────────────────────┴───────────────────┴──────────────────────────┘

   Fixed in code (claude_client.py):
     thinking = adaptive       → AI decides how much to think
     format   = JSON schema    → API forces the answer shape
     cache    = system prompt  → repeat calls are cheaper
     streaming = on            → no timeout issues on long answers

   ⏱️ Worst case wait = 180s × 2 tries = 6 min

══════════════════════════════════════════════════════════
 6️⃣  ERROR HANDLING  (every risky step is in try/except)
══════════════════════════════════════════════════════════

   ┌──────────────────────┬──────────────────────────────────┐
   │ What happened        │ User sees                        │
   ├──────────────────────┼──────────────────────────────────┤
   │ 🔑 Wrong API key      │ "API key is invalid"             │
   │ 🚫 No permission      │ "Key not allowed for this model" │
   │ 🔎 Wrong model name   │ "Model not found"                │
   │ ⏳ Too many requests  │ "Wait a minute, try again"       │
   │ 🧾 Bad request        │ "Request rejected, see logs"     │
   │ ⌛ Timeout            │ "AI took too long"               │
   │ 📡 No internet        │ "Could not reach Claude"         │
   │ 🌩️ Server error       │ "Claude API error (code)"        │
   │ 🛑 AI refused         │ "AI declined this resume"        │
   │ ✂️ Answer cut off     │ "Increase CLAUDE_MAX_TOKENS"     │
   │ 🧩 Broken JSON        │ "Answer not valid JSON"          │
   │ 💥 Anything else      │ "Unexpected error, see logs"     │
   └──────────────────────┴──────────────────────────────────┘

   Full technical details always go to the logs.
